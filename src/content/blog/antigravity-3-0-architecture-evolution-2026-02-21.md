# Antigravity 3.0 异构多智能体全闭环职能关系图谱

## 1. 核心架构演进：从“人肉路由器”到“自治制片人”

在 Antigravity 2.0 时代，系统虽建立了多智能体协作流，但由于本质上仍遵循“强同步、重审批”的瀑布流逻辑，导致人类指挥官被迫处理大量的节点 ACK（确认）请求与上下文搬运，沦为高负荷的“人肉路由器”。3.0 架构的演进核心在于彻底打破审批死锁，通过底层协议的重构实现系统自治。

**Antigravity 3.0 的三大核心原则：**

* **异步 (Async)**：节点间不再强制同步等待回复，通过消息总线实现非阻塞流转，彻底消灭“全员等待”导致的时间损耗。
* **解耦 (Decoupled)**：每个智能体仅消费最小化的“意图契约”与“文件锚点”，从物理层面杜绝全量代码投喂导致的上下文爆炸。
* **事件驱动 (Event-Driven)**：流程推进完全由明确的信号（如 Webhook、Git 提交）触发，用代码逻辑取代人工的复制粘贴。

在这种架构下，人类的角色从“通信协调员”正式转型为**“制片人 (Producer)”**——仅需定义顶层意图与最终的阻塞仲裁，其余执行细节由智能体在闭环中自主完成。

## 2. 四大核心智能体职能矩阵

3.0 框架基于异构算力特性，对不同智能体进行了严密的岗位性格（温度）映射，确保在极寒理智与创意发散之间取得平衡。

| 角色名称 | 核心职责 | 推荐算力/模型 | 建议温度 | 执行特性 |
| :--- | :--- | :--- | :--- | :--- |
| **主持人 (Orchestrator)** | 意图解析、契约起草、跨节点任务分发、本地工具链调度。 | Gemini 1.5 Pro | 0.6 - 0.8 | 强调意图解析与契约广播，拥有最高系统调度权限。 |
| **工兵 (Executor)** | 纯代码逻辑实现、核心 Bug 修复、容器镜像构建。 | DeepSeek-V3/R1 或 Gemini 3.X | 0.0 - 0.2 | 强调逻辑严谨性与低温输出，严禁任何形式的幻觉。 |
| **叙事官 (Narrator)** | 营销文案、视频脚本撰写、产品 Storytelling 策划。 | Qwen-Max / 豆包 / Kimi | 1.0 - 1.5 | 强调创意发散与感性共鸣，高度匹配本土网感。 |
| **史官 (Scribe)** | 异步监听里程碑、提炼干货摘要、向量化存储记忆。 | Qwen-Turbo / Gemini Flash | 0.1 | 强调中性记忆，其中 Qwen-Turbo 尤擅处理中文营销细节。 |

这些角色在两条互不干扰的“平行轨道”上协作，确保工程的确定性与营销的爆发力完全解耦。

## 3. 轨道 A：软件工程生命周期（极寒理智轨道）

软件工程轨道追求极致的逻辑上限与安全性，遵循“意图 -> 契约 -> 执行 -> 审计”的严苛闭环。

1. **立项阶段 (PM/主持人)**：主持人接收人类模糊意图，起草**“意图契约 (Intent Spec)”**。该契约不仅定义了变更目标，还规定了严格的输入输出约束与验收标准。
2. **执行阶段 (工兵)**：工兵（Gemini 3.X/Claude 4.X）接收契约，并受到**“文件锚点 (File Anchors)”的物理约束。仅允许对锚定的特定文件进行读写，这是防御“上下文爆炸 (Context Explosion)”**的第一道防线。
3. **审计阶段 (Auditor)**：由 DeepSeek-V3/R1 担任严苛审计官。引入**“乐观契约 (Lazy Consensus)”**机制：
  * **P2/P3 级变更**：审计官在 TTL 窗口（1-30 分钟）内异步扫描。若无显式拒绝（NACK），系统默认通过。
  * **P0/P1 级变更**：涉及核心 API 或数据库 Schema 的破坏性变更，必须触发**“阻塞同步 (Blocking Sync)”**，由人类或主持人强行介入 ACK。
4. **交付阶段 (SRE)**：运维智能体接管 run_command，通过 1Panel 完成 Docker 构建、域名映射与自动化部署。

**关键点**：该轨道通过极低的温度设定和精细的权限锚定，实现了对“逻辑安全性”与“执行一致性”的极致追求。

## 4. 轨道 B：市场品牌营销矩阵（文本驱动视觉轨道）

营销轨道全面拥抱国产 LLM 生态，利用其对本土语境的深度理解，实现垂直赛道的内容爆发。

1. **脚本生成**：利用 DeepSeek 或豆包生成硬核脚本。严格执行“3s 黄金钩子 + 60s 主体 + CTA”模式，并覆盖 IOT、能源、养老等 16 个垂直赛道。
2. **视觉匹配**：由 Qwen-VL 或 GLM-4V 执行视觉打标（visual_tagger），根据脚本中的 `[Visual]` 标签定向匹配素材库中的视觉资产。
3. **资产闭环**：通过 Webhook 将产出的脚本与素材实时推送至飞书 (Lark) 供人工校对，确保内容合规。

**重点说明**：此轨道之所以全面拥抱国产模型，源于其在处理本土语义钩子、社交媒体转化逻辑及长文本营销叙事方面的天然优势。

## 5. 史官系统：跨系统的记忆长城与 RAG 机制

史官系统作为“观察者插件”运行，在不干涉业务主流程的前提下，完成双轨知识的永久化沉淀。

* **记忆标签分层（Namespace Isolation）**：
  * `[Namespace: technical_infra]`：记录架构决策 (ADR)、Bug 复盘及部署拓扑。
  * `[Namespace: brand_asset]`：记录高转化脚本模版、视觉提示词资产及 ROI 数据。
* **防洪机制 (Noise Reduction)**：
  * 史官仅在检测到特定前缀（如 `Fix:`, `Feature:`, `Marketing-ROI:`）或人类显式指令时触发记录，避免记忆库沦为无意义的数据垃圾场。

* **资产存储策略对比**：

| 资产类型 | 存储状态 | 内容定义 | Token 节约效益 |
| :--- | :--- | :--- | :--- |
| **冷资产 (Cold)** | 缓存区 | 全局标准、编码规范 | 极高（通过 Prompt Caching 实现近零成本读取） |
| **温资产 (Warm)** | 挂载区 | 当期项目 PRD、API 规范 | 中（里程碑切换时更新缓存） |
| **热资产 (Hot)** | 传输区 | 当前意图契约、文件路径锚点 | 低（随每次任务实时传输） |

史官将提炼后的摘要通过 Embeddings 技术注入 PostgreSQL (pgvector)，构建起一道双轨隔离的记忆长城。

## 6. 中小企业 (SME) 降本增效优化方案

针对算力成本敏感场景，3.0 提供了收缩供应商、最大化缓存红利的优化方案。

* **精简版模型组合**：
  * **核心大脑**：Gemini 1.5 Pro（负责统筹、PRD 与工程主控）。
  * **执行与审计**：Claude 3.5 Sonnet（负责核心代码与审计）。
  * **本土全能**：Qwen 系列（负责营销线、多模态打标与史官记录）。

> **“一鱼多吃”策略**： 
> 通过模型收敛实现“垂直集成”。利用 Gemini 1.5 家族（Pro 负责脑力，Flash 负责苦力），让 Flash 节点直接继承 Pro 节点已生成的 Prompt Caching（上下文缓存）。这不仅减少了多厂商 API 对接的复杂度，更通过前置文档的零成本复用大幅提升了投资回报率 (ROI)。

## 7. 结论：MAS 架构下的协作图谱总览

Antigravity 3.0 的核心灵魂在于**“异步、解耦、克制”**。它不仅是一套智力的堆砌，更是一套关于系统边界的艺术。通过平行双轨的物理隔离，引入乐观共识与史官记录，人类终于从琐碎的通信中抽身，回归到战略定义与最终仲裁的“制片人”位点。

**“最好的管理艺术，正是让智能体在各自的轨道上，顺着契约的逻辑自主奔流。”**
